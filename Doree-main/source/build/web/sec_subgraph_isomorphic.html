    Section 3.4 Subgraphs and Isomorphic Graphs

    There are many different ways to draw a graph. Suppose that you and I each draw a graph and our graph drawings look different. How do we know if our graphs are actually the same graph (isomorphic)? For example, are any of the graphs \(G_1\text{,}\) \(G_2\text{,}\) and \(G_3\) drawn in Figure 3.4.1 the same (isomorphic)?
    🔗
    Recognizing when two apparently different objects are, for all mathematical purposes, the same or different is a powerful skill. For example, suppose that we are modeling a problem and encounter a new graph \(G\text{,}\) a graph that we know nothing about. But then we realize that \(G\) is isomorphic to a graph \(H\) that we know well. Then everything that is true about the known graph \(H\) is automatically true for the new graph \(G\) as well. The concept of isomorphic occurs throughout mathematics.
    🔗
    There is no known efficient algorithm for determining if two graphs are isomorphic. We begin this section with a visualization tool that can help and close this section by introducing vocabulary about graphs that live within other graphs (subgraphs), which can also offer clues about whether two graphs are isomorphic.
    🔗

    Subsection 3.4.A Planarity

    When we draw a graph, it is acceptable to have edges that cross each other. Any point of intersection of those edges in the drawing is not a vertex. For example, the complete graph \(K_5\) is typically drawn with many edges crossing, as in Figure 3.4.2.
    🔗
    In some situations, we might prefer to draw a graph without edges crossing. For example, if the graph were modeling a physical system, such as train tracks or electrical wires, we might want to avoid edge crossings, or at least find a drawing with as few edge crossings as possible. It is reasonable to ask whether a graph can be drawn without crossings. For example, can you find a way to draw \(K_5\) without any edge crossings?
    🔗
    We formalize this idea with a definition.
    🔗

    Definition 3.4.3. Planar graph.

     
    1. An edge crossing in the drawing of a graph is a point of intersection of two edges other than at a vertex.
      🔗
      🔗
    2. A graph is planar if it can be drawn in the plane without any edge crossings. For example, consider the graph \(G\) drawn in Figure 3.1.3. In the fourth drawing of \(G\text{,}\) the edges \(\{3,4\}\) and \(\{1,2\}\) cross, but no edges cross in the first three drawings of \(G\text{.}\) Thus, \(G\) is planar.
      🔗
      🔗
    3. A graph is nonplanar if it cannot be drawn in the plane without any edge crossings. For example, it turns out that the complete graph \(K_5\) is nonplanar.
      🔗
      🔗
    🔗
    🔗
    Let’s look at an activity redrawing planar graphs without edge crossings.

    Subsection 3.4.B Isomorphic Graphs

    The three graphs in Figure 3.4.1 have many common properties. For example, each graph has six vertices, five edges, and degree sequence 3, 2, 2, 1, 1, 1. They also all have chromatic number two. But they are not all isomorphic.
    🔗
    Here is the formal definition.
    🔗

    Definition 3.4.7. Isomorphic Graphs.

     
    1. Two graphs \(G\) and \(H\) are isomorphic, denoted \(G \cong H\text{,}\) if it is possible to label the vertices of \(G\) and the vertices of \(H\) in such a way that \(G\) and \(H\) have the same set of vertices and the same set of edges. For example, the graphs \(G_1\) and \(G_2\) in Figure 3.4.1 are isomorphic. We show a common vertex labeling in Figure 3.4.8. You can check that each graph has the vertex set
      \begin{equation*} \{a, b, c, d, e, x\} \end{equation*}
      and the edge set
      \begin{equation*} \{\{a,b\}, \{b,c\}, \{c,d\}, \{d,e\}, \{c,x\}\}\text{.} \end{equation*}
      (By the way, it is acceptable to abbreviate edges using strings. For example \(\{a,b\}\) may be abbreviated \(ab\) when clear from context.)
      🔗
      🔗
    2. A planarity-style move on a graph drawing consists of moving one vertex \(v\) to a different location and redrawing the edges from \(v\) in its new location to each of \(v\)’s neighbors.
       1 
      These moves are named for the game “Planarity” from Activity 3.4.A.
      🔗
      🔗
    🔗
    🔗
    These moves give us another way to work with graph isomorphism.
    🔗

    Remark 3.4.9. Planarity-style moves.

    Graphs \(G\) and \(H\) are isomorphic exactly when we can transform a graph drawing of \(G\) into a graph drawing of \(H\) using a sequence of planarity-style moves. While visualizing such a transformation is a useful way to decide if two graphs are isomorphic, to prove that two graphs are isomorphic, you need to label the vertices according to the definition. If you can see the transformation, just follow the vertices to see what the labels should be. For example, we can think of transforming the graph \(G_1\) into the graph \(G_2\) from Definition 3.4.7 by shifting the vertex \(x\) up and to the right and the vertices \(d\) and \(e\) down and to the left.
    🔗
    🔗
    When two graphs are complicated, it can be useful to compare their complements instead. Note that if \(G\) and \(H\) are isomorphic and labeled with the same vertices and edges, then that labeling shows that \(\overline{G}\) and \(\overline{H}\) have the same vertices and edges and so \(\overline{G}\) and \(\overline{G}\) are also isomorphic. We have the following result.
    🔗

    Theorem 3.4.10. Isomorphic Complements.

    For graphs \(G\) and \(H\) we have \(G \cong H\) exactly when \(\overline{G} \cong \overline{H}\text{.}\)
    🔗
    🔗
    Here is an example of using the complement to prove that two graphs are isomorphic.
    🔗

    Subsection 3.4.C Subgraphs and Trees

    A common type of graph used to store information in a computer is a tree. We saw examples of possibility trees in Section 2.1. Trees are defined using the concepts of subgraph and connectivity, so we start there.
    🔗

    Definition 3.4.19. Subgraph.

    The graph \(H\) is a subgraph of the graph \(G\) if each vertex of \(H\) is a vertex of \(G\) and each edge of \(H\) is an edge of \(G\text{.}\) Note that since \(H\) is a graph, each edge of \(H\) necessarily contains two vertices of \(H\text{.}\) For example, in Figure 3.4.20, the graph on the left is a subgraph of the graph on the right.
    🔗
    🔗
    In Figure 3.4.20, we draw the vertices of the subgraph \(H\) in the same position as they appeared in \(G\text{,}\) but that is not required.
    🔗

    Example 3.4.21. Less obvious subgraphs.

    Consider the graph \(G\) from Figure 3.4.20. Which of the following graphs are subgraphs of \(G\text{?}\)
    1. The cycle \(C\) drawn in Figure 3.4.22.
      Solution.
      The cycle \(C\) is a subgraph of \(G\) because each of \(C\)’s vertices (\(b\text{,}\) \(c\text{,}\) \(d\text{,}\) and \(e\)) and each of \(C\)’s edges (\(\{b,c\}\text{,}\) \(\{c,d\}\text{,}\) \(\{d,e\}\text{,}\) and \(\{e,b\}\)) are in \(G\text{.}\) Note that \(C\) is the cycle \(C_4\text{,}\) so we say \(C_4\) is a subgraph of \(G\text{.}\)
      🔗
      🔗
      🔗
      🔗
    2. The path \(P\) drawn in Figure 3.4.23.
      Solution.
      The path \(P\) is a subgraph of \(F\) because each of \(P\)’s vertices (\(a\text{,}\) \(c\text{,}\) \(d\text{,}\) \(e\text{,}\) and \(f\)) and each of \(P\)’s edges (\{f,c\}, \{c,b\}, \{b,e\}, and \{e,a\}) are in \(F\text{.}\) Note that \(P\) is the path \(P_5\text{,}\) so we say \(P_5\) is a subgraph of \(G\text{.}\)
      🔗
      🔗
      🔗
      🔗
    3. The graph \(J\) drawn in Figure 3.4.24.
      Solution.
      The graph \(J\) is not a subgraph of \(G\) because \(\{a,d\}\) is an edge in \(J\) but not in \(G\text{.}\)
      🔗
      🔗
      🔗
      🔗
    4. The graph \(D\) drawn in Figure 3.4.25.
      Solution.
      The graph \(D\) is a subgraph of \(F\) since each vertex and edge in \(D\) is in \(G\text{,}\) even though \(D\) has two separate pieces.
      🔗
      🔗
      🔗
      🔗
    🔗
    🔗
    We introduce a bit more vocabulary about subgraphs.
    🔗

    Definition 3.4.26. Cyclic subgraphs.

     
    1. A cyclic subgraph of a graph is a subgraph that is a copy of \(C_s\) for some integer \(s \ge 3\text{.}\) For example, the graph \(C\) from Example 3.4.21 was a cyclic subgraph of the graph \(G\text{.}\)
      🔗
      🔗
    2. A graph \(G\) contains an \(s\) cycle if \(C_s\) is a subgraph for some \(s \ge 3\text{.}\) For example, the graph \(G\) in Figure 3.4.20 contains several 3-cycles, a couple of 4-cycles, and 5-cycle.
      🔗
      🔗
    3. A graph is acyclic if it does not contain any cyclic subgraphs. For example, the path graphs \(P_s\) are acyclic.
      🔗
      🔗
    🔗
    🔗
    Let’s count all the cycles in a graph.
    🔗

    Example 3.4.27. Counting cycles.

    Count all the cycles in the graph \(G\) in Figure 3.4.20.
    🔗
    Solution.
    First, there are three 3-cycles: one with vertices \(a\text{,}\) \(b\text{,}\) and \(e\text{;}\) a second with vertices \(b\text{,}\) \(d\text{,}\) and \(e\text{;}\) and a third with vertices \(b\text{,}\) \(c\text{,}\) and \(d\text{.}\)
    🔗
    Next, there are two 4-cycles: one with vertices \(a\text{,}\) \(b\text{,}\) \(d\text{,}\) and \(e\) and the other with vertices \(b\text{,}\) \(c\text{,}\) \(d\text{,}\) and \(e\text{.}\)
    🔗
    Lastly, there is one 5-cycle with vertices \(a\text{,}\) \(b\text{,}\) \(c\text{,}\) \(d\text{,}\) and \(e\text{.}\)
    🔗
    🔗
    🔗
    In most networks, we want to maintain connectivity. Casually speaking, a graph is connected if there are no separate pieces, which is difficult to define directly. We give a formal definition of connected here.
    🔗

    Definition 3.4.28. Paths and connectivity.

     
    1. A path in a graph is a subgraph that is a copy of \(P_s\) for some integer \(s \ge 1\text{.}\) For example, the graph \(P\) from Example 3.4.21 was a path in the graph \(G\text{.}\)
      🔗
      🔗
    2. A \(uv\)-path is a path with endpoints \(u\) and \(v\text{.}\) For example, the graph \(P\) from Example 3.4.21 is a \(fa\)-path (or an \(af\)-path) in the graph \(G\text{.}\) A single vertex \(u\) is considered a \(uu\)-path.
      🔗
      🔗
    3. A graph \(G\) is connected if for all vertices \(u\text{,}\) \(v\) there exists a \(uv\)-path in \(G\text{.}\) For example, the graph \(G\) in Figure 3.4.20 is connected, as are its subgraphs \(C\) and \(P\) from Example 3.4.21.
      🔗
      🔗
    4. A graph \(G\) that is not connected is disconnected. For example, the subgraph \(D\) in Example 3.4.21 was disconnected because, for example, there does not exist a \(cd\)-path in \(D\text{.}\)
      🔗
      🔗
    🔗
    🔗
    Let’s look at an example.
    🔗

    Example 3.4.29. Finding paths.

    Consider the graph \(G\) drawn in Figure 3.4.30. Find an \(hd\)-path in \(G\text{.}\) Is it unique?
    🔗
    Solution.
    One \(hd\)-path is \(hcd\text{.}\) It is not unique. For example \(hjibcd\) is another \(hd\)-path as is \(hibcd\text{.}\)
    🔗
    🔗
    🔗
    We can now define a tree. Many applications of graph theory in computer science use trees.
    🔗

    Definition 3.4.31. Tree.

    A tree is an connected acyclic graph. For example, the path graphs \(P_s\) are trees for \(s \ge 1\text{.}\) The graph \(T\) drawn in Figure 3.4.32 is also a tree.
    🔗
    🔗
    A tree needs to be connected and acyclic. If either condition fails in a graph, then that graph is not a tree.
    🔗

    Example 3.4.33. Not a tree.

    Explain why each graph is not a tree.
    1. The graph \(G\) drawn in Figure 3.4.30.
      Solution.
      The graph \(G\) is connected, but it is not a tree because it is not acyclic. For example, \(G\) contains a 3-cycle with vertices \(i\text{,}\) \(j\text{,}\) and \(h\text{.}\) By the way, \(G\) also contains a 4-cycle with vertices \(b\text{,}\) \(c\text{,}\) \(h\text{,}\) and \(i\) and a 5-cycle with vertices \(b\text{,}\) \(c\text{,}\) \(h\text{,}\) \(i\text{,}\) and \(j\text{.}\)
      🔗
      🔗
      🔗
      🔗
    2. The graph \(D\) drawn in Figure 3.4.25.
      Solution.
      The graph \(D\) is acyclic, but it is not a tree because it is disconnected.
      🔗
      🔗
      🔗
      🔗
